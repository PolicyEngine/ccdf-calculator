# CCDF child care subsidy dashboard: plan

Public dashboard at `policyengine.org/us/ccdf-calculator` covering the 51 state
child care subsidy programs (50 states + DC) funded under the Child Care and
Development Fund (CCDF) and encoded in policyengine-us.

## Scope (agreed 2026-09-09)

| Page | Purpose | Data layer |
|---|---|---|
| Calculator | Pick a state, describe the household (parents, children's ages, income, care schedule, provider type and quality tier), see the monthly subsidy, the family copay, and eligibility. Chart of subsidy vs income. | Precomputed grid for the reference households; live household API (`POST https://api.policyengine.org/us/calculate`) for the exact household the user enters. |
| Compare states | Map and ranked bar of subsidy or copay for a chosen reference household at a chosen income. Table of effective entry income limits (as % SMI and % FPL) and program facts. | Precomputed grid + `policy_index.json` built from parameter YAML. |
| Population impact | Estimated eligible families, enrolled families and annual subsidy dollars by state from the Microcosm microsimulation. Secondary feature. | `impact.json` produced by `scripts/microsim.py` (heavy; run separately). |

## Model facts that drive the design

- Every state program is aggregated by the federal variable
  `child_care_subsidies` via the program list in
  `gov/hhs/ccdf/child_care_subsidy_programs.yaml`.
- Shared inputs read by most states: `employment_income`,
  `weekly_hours_worked_before_lsr`, per child `childcare_hours_per_day`,
  `childcare_days_per_week`, `childcare_attending_days_per_month`, and the SPM
  unit's `spm_unit_pre_subsidy_childcare_expenses` (the provider charge).
- 29 states read `meets_ccdf_activity_test` (a boolean input). Nevada returns
  zero unless it is set; the calculator sets it from "parent works or studies".
- Most states have their own provider type enum and many have a quality tier
  enum. Maryland defaults its provider type to `NONE`, which pays zero, so the
  calculator always sets a provider type.
- 30 states read `county_fips`; the reference households use each state's
  most populous county (see `scripts/state_config.py`).
- Subsidy formula shape is common: `min(provider charge, state max rate) -
  family copay`, summed over eligible children. The precomputed grid assumes a
  provider charge at or above the state maximum, so it reports the maximum
  subsidy for that household, and separately reports the copay.

## Reference household grid (precomputed)

| Dimension | Values |
|---|---|
| Adults | 1, 2 (second adult also works 40 hours) |
| Children | one of: `infant` (age 1), `preschool` (age 3), `school` (age 7), `two` (3 + 7), `three` (1 + 3 + 7) |
| Earned income | $0 to $150,000 per year in $1,000 steps (151 points), via PolicyEngine axes |
| Care schedule | under 5: 8 h/day, 5 days/week; school age: 3 h/day, 5 days/week; 22 attending days/month |
| Provider | the state's default provider type (a licensed center) and base quality tier |
| Outputs | monthly subsidy, monthly copay, eligible flag, plus SMI and FPL for the unit |

10 structures × 151 income points per state, computed with one simulation
per structure. Output: `public/data/{ST}.json` and `public/data/metadata.json`.

## Live calculation

`src/lib/api.ts` builds the same situation the precompute uses, with the
user's exact ages, hours, provider charge, provider type and quality tier,
and posts it to the v1 household API. It requests `child_care_subsidies`, the
state's monthly subsidy variable, copay variable and eligibility variable
(from `public/data/state_inputs.json`, generated by
`scripts/build_state_inputs.py`).

## Repo layout

```
scripts/
  state_config.py        per-state contract: variables, county, provider default
  calculator.py          create_situation() shared by precompute and probes
  precompute.py          reference-household grid -> public/data/*.json
  build_state_inputs.py  enum options + variable names -> public/data/state_inputs.json
  policy_index.py        parameter YAML -> public/data/policy_index.json
  microsim.py            Microcosm run -> public/data/impact.json
src/app/                 Next.js App Router pages (calculator, compare, impact)
src/components/          InputPanel, ResultsPanel, BenefitChart, StateMap, StateRanking, PolicyTable
src/lib/                 dataLookup.ts, api.ts, situation.ts, niceTicks.js
public/data/             generated JSON (committed)
```

## Deployment

Vercel project `ccdf-calculator`, base path `/us/ccdf-calculator`, registered
in policyengine-app-v2 `appZoneRoutes.ts` and `apps.json` like tanf-calculator.
